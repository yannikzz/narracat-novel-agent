# 发布说明正文

每一版一个文件：`<版本号>.md`（如 `0.3.2.md`），内容是**这一版对用户是什么**。

发版时 `scripts/release.mjs` 会把它排在发布说明最前面，后面自动接上通用样板
（怎么升级 / 首次安装 / Windows 未签名提示）。

## 为什么是文件，不是发版时在终端里现问

这段话要提前写、要能在 PR 里被人审、要能改。发版当口对着终端敲一段中文正文，
既难写也没人会认真写——而发布说明是这个版本对外唯一的门面。

## 写什么

用户关心的是**能感觉到什么变化**，不是提交列表。一句话说清这版是什么，
后面跟几条具体的。反面例子是把 `git log` 抄一遍。

```markdown
这一版加了**匿名使用统计**，用来判断哪些功能真的有人用、哪些该改。

- 首次启动会有一屏说明，可以选择不参与；之后在「设置 → 安全与项目」里随时能关
- **小说正文、章节标题、大纲、人物设定、书名与 API Key 一个字都不传**
- 完整事件清单见 [FAQ](...)
```

支持 Markdown（GitHub Release 页按 Markdown 渲染），可以放链接。

## 不写会怎样

不阻断发版——紧急修复可能真没什么好说的。但预检会出一条 `!` 提醒，
且发布说明会只剩通用样板，答不了「这一版改了什么」。

## 为什么会有这套东西

0.3.1 那次，CI 建 draft 时写的内部占位串（「草稿：Windows 产物已由 CI 就位……」）
被当成发布说明发给了所有用户，连「Windows 未签名会撞 SmartScreen」那段必要告知
都一起丢了。当时全量测试绿、CI 绿、八件产物齐全、更新链两端 200——**四条判据全对，
发出去的东西对用户仍然是不像样的**。

修完根因（发布说明改在 publish 那一步定稿）之后，还差一件事：样板答不了
「这一版改了什么」。这个目录就是那一件。发版最后一道人工确认闸现在也会把
**真正会发出去的发布说明原样打出来**——用户会读到什么，就该在按下确认前被看到。
