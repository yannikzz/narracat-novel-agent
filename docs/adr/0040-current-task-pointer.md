# ADR-0040: 当前任务指针——把「下一步」从状态页提升为侧边栏常驻

Status: Accepted

Date: 2026-09-01

## Context

0.3.2 上线后的首批遥测（43 台设备）暴露一个漏斗断点：**43 台启动 → 32 台新建项目 → 只有 9 台
真的写了章节**。掉队的 25 台不是随便看看——8 台停留超过 3 小时（最长 14.4 小时），把立项卡、
模型服务、记忆星图、参考作品、能力包挨个点了一遍，**零报错**，然后 22 台再没回来。

诊断时先怀疑过写作入口藏得太深（「写本章」按钮只在点进"正好是当前章"的那一章时才出现），
那条死胡同已单独修掉。但真正让人意外的是：**产品里早就有一套完整的下一步引导**——状态页
（`WorkbenchStatusPanel`）有生命周期 stepper 和按 `project.status` 切换的唯一主行动
（`resolveStatusNextStep`），而且首次进入工作台默认就落在那一页。

所以问题不是「没有引导」，而是**引导只长在一个页面上，人一离开就再也看不到**。遥测里那 25 台
在各模块间打转的轨迹，与写成功的 9 台几乎一模一样——同样的模块、同样的顺序、更长的时间，
唯一的区别是最后没按下「写」。

诊断中还发现两个更基础的问题：

1. **真实卡点其实是未知的。** 立项卡对话（`setup`）与规划大纲（`plan`）都是 Agent run，全部
   共用 `agent:start-run` 一个 IPC 通道，而埋点挂在 IPC 装配处、看不见 command——这两步此前
   完全没被计入任何模块。「32 台建了立项卡」的正确读法其实是「32 台**新建了项目**」
   （`novel:create-project` 也归在 `premise` 模块下）。
2. **`project.status` 的四阶段划分与引擎的真实创作链不一致。** 引擎各命令的前置检查定义的顺序是
   立项卡 → **世界观与角色** → 大纲 → 正文，而 `status` 只看「有没有 setup 数据」和
   「`planned` 是否 > 0」，**对世界观与角色这一步完全无感**。照 `status` 做指针，会在用户做完
   立项卡后直接说「规划全书大纲」，而用户点进去跑 `plan` 时，引擎又会问「要不要先去创建
   主要角色」——指针把人往前推，引擎再把人拦回来。

## Decision

### 一、把「下一步」提升为侧边栏常驻的**当前任务指针**

放在 `data-workbench-sidebar-fixed-menu` 区（`shrink-0`，不随章节目录滚动），走到哪都在。

它**不是新手引导**：永久常驻、不可关闭、不随「出师」消失。理由是「我现在该干什么」不是新手
专属问题——写到第 80 章的作者同样需要一键回到当前工作面。做成只给第一本，既要定义一个没有
非任意定法的「出师」阈值，又把一个长期有用的东西做成了一次性的。

副作用是它顺带解决了「用户记不住引导」——**常驻的东西不需要被记住**。

### 二、点击只导航，不发起 Agent run

状态页的下一步按钮是 `kind: 'agent'`，一点就跑。搬成常驻元素后语境变了：侧边栏一直在那儿，
误触的代价是意外启动一个跑十几分钟、要花钱、不好取消的任务。

指针改为纯导航，到达目的地后由该处**既有的** Empty guide 主按钮二次确认。代价是多一次点击，
换来的是常驻元素必须具备的安全性；也与同期修掉的「本章还没轮到 → 去写第 N 章」保持同一套
心智（指针类元素只负责把人带到位置）。

### 三、创作链补上「世界观与角色」这一格，且只建议不阻塞

```
needs-setup                 → 建立创作根基
needs-outline + 无角色      → 建议先创建主要角色     ← 新增
needs-outline + 有角色      → 规划全书大纲
ready / in-progress         → 写第 N 章 / 继续第 N 章
done                        → 收起
```

判据直接沿用 `plan.md` 自己用的那条：`bible/characters/*.md` 是否为空。**不用
`checkpoint.lastCommand`**——它只记最后一次命令，跑完 `world` 再跑别的就被覆盖，不可靠。

**状态页的生命周期 stepper 同步从四格改为五格**：立项 → **设定** → 大纲 → 连载 → 完结。
只改指针不改 stepper 会让两处对不上——指针让作者去创建角色，状态页却显示当前在「大纲」。
用词取「设定」而非「角色」：`world` 同时管世界观与角色，且与工作台「设定集」的既有称呼一致，
点过去就是那里（判据仍只看角色档案，与引擎 `plan.md` 的口径一致）。

跳过设定的作者不会卡住：直接做大纲会让 `status` 进 `ready`，stepper 顺势推到「连载」，
之前的格子一律显示为已走过——stepper 表达的是「当前在哪一阶段」，不是逐项打卡。

**「可跳过」不存任何状态。** 用户想跳过就自己去点大纲（本来就能点）；大纲一做完 `status` 变
`ready`，指针自然往前走，再也不会退回「创建角色」。因此指针**永远只有一个主按钮**，「可跳过」
只体现在文案措辞上（「建议先…」）。

### 四、完成感依附在指针上，不新增第三层通知

状态一变，指针自己变，并短暂高亮让变化被看见。**不加 toast**：run 完成已有通知铃 + 系统原生
通知，再加一条就是同一件事被告知三次。

### 五、参考作品不进主链

`setup` 会读参考作品的产出来推断答案、少问用户几轮，所以它越早加越值钱。但它完全可选，放进
主链等于在用户最想开始的时候多一道坎。主链保持最短。

### 六、不做一次性的界面导览浮窗

遥测提供了反证：掉队的 25 台把各模块**全都点过一遍**，探索界面没有障碍，卡的不是「这是什么」
而是「接下来轮到哪一步」。浮窗也与本 ADR 的核心判断相悖——它同样是会消失的信息，治不了
「离开就看不见」这个病。

### 七、连带修正埋点的两处漏采

- `plan` / `setup` 按命令补记（归属判断收口在 `telemetry/ipc-modules.ts` 的命令表，不散进业务代码）。
- **`novel:create-project` 从 `premise` 拆到独立的 `project-create` 模块**。否则 `setup` 补了也白补：
  `recordFeatureUsed` 按天去重，新建项目会把立项卡对话的信号淹掉，仍然分不清「开了个坑」和
  「真做了立项卡」。

**这三项要重新告知，`CURRENT_TELEMETRY_NOTICE_VERSION` 1 → 2。**

本 ADR 初稿曾断言「这是修复漏采、采集的行为集合没有扩大，不需要 bump」，理由是
`outline`/`premise` 本就在 `TELEMETRY_MODULES` 里。**这个论证是错的**，外审（Codex）指出后已
更正：模块枚举里有这个值，不等于那个用户行为被采集过——立项卡对话与规划大纲这两个动作，
改动之前**一条事件都没发过**，改动之后会发。对用户而言这就是新增采集项，不管它落到哪个旧标签
上。`TelemetryNotice.tsx` 的红线写的是「改口径（尤其新增采集项）时必须同时改文案并 bump」，
这里正中红线。ADR-0039 整篇的立论就是「没说清楚就采集」才是翻车的原因，在自己写的红线上
违规尤其不可接受。

告知文案相应加了一句限定语（点名新建项目 / 立项卡对话 / 规划大纲三样），标题与「你写的每一个
字都不会离开这台电脑」的承诺块一字未动——它们没有变化，改了反而制造「承诺是不是松动了」的
疑虑。`docs/faq.md` 的公开模块数同步 16 → 17。

`TELEMETRY_SCHEMA_VERSION` **不 +1**：它的定义是「字段语义变更时 +1，服务端据此分辨新旧
客户端」，而这次 `module` 字段语义没变、只是取值多了一个；Worker 白名单按 key 名校验、不看
取值，服务端没有分辨新旧的需求。为取值集合的变化去动它，会让这个版本号失去含义。

## Consequences

- 「我现在该干什么」在工作台任何位置都有答案，且新老作者通用。
- 指针与引擎的创作链对齐，不再出现「推一下又拦一下」。
- 下一版的遥测能第一次看清 `新建项目 → 立项卡 → 大纲 → 写章节` 的真实漏斗。
- 需要新增一条数据通路让 App 知道有无角色文件（`bible/characters/*.md`），这是新增的契约字段。
- **常驻元素会变成背景噪声**（banner blindness）。缓解手段是状态变化时短暂高亮、完结即收起，
  只能减轻不能根除。
- **这个方案押的是「下一步不跟随用户」与「没有完成感」两个假设，是在数据到齐之前下的注。**
  如果真实根因是「卡在配模型」或「立项卡长对话中途放弃」，它治不好。埋点已同期补上，
  下一版发布后可以回头验证这一注押得对不对——若押错，本 ADR 应被 supersede 而不是打补丁。
- **存量用户会再看一次告知屏**（`CURRENT_TELEMETRY_NOTICE_VERSION` 1 → 2），并且在确认前
  零发送。这是 ADR-0039 设计的正确行为，代价是一次打扰——所以文案加了限定语而不是原样重放，
  让老用户看得出增量在哪。
- 已知盲区：世界观与角色（`world`）这一步仍然没有埋点，指针虽然会指向它，但做没做成看不见；
  另外用户在输入框里自己打字触发的命令是 `freeform`，命令表记不到。
- **外审（Codex）在合并前拦下 6 条**，其中两条是真缺陷而本地测试全绿：连载路径的完成高亮
  从不触发（判据用 `action.id`，而那一路 id 恒为 `status-next-write`，章号只在 label 里），
  以及「可跳过」只写在从不渲染的 `action.description` 里。共同的病根是**测试断言的是 action
  数据、而作者看见的是 DOM**——补的回归测试一律改为断言渲染结果。这与本仓「eager 预加载单测
  全绿、真机不触发」是同一种病。
